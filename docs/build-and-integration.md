# STILL desktop integration and Windows build

## 1.0.1 remediation source workflow

The current source version is `1.0.1`. The iteration-2 status below describes the historical delivered baseline; its test totals are not a fresh run of the remediation tree. The source-only recovery record is [source-baseline-0bf.json](source-baseline-0bf.json), and the current entry point for contributors is [README](../README.md).

For source checks, install the locked dependencies with `npm ci --ignore-scripts --no-audit --no-fund`, then run `npm run lint`, `npm test`, and `npm run build`. Dependency installation is the preparation step; the default checks must run offline without a real player, Apple host, native compiler, music library, or historical local evidence. The CI workflow uses these same steps on Windows and Linux. Installing with `--ignore-scripts` deliberately does not download or start Electron, and `build` is a static source/artifact check rather than application packaging.

ESLint enforces only `no-unused-vars` and `no-console`. The configuration lists individual CLI entry points and the test that captures their output as explicit `no-console` exceptions; other scripts keep both rules. Formatting is not a gate. Native and other real integration checks require their own explicit opt-in; do not add them back to the default test path.

The desktop entry point is CommonJS `src/main/main.js`. It explicitly recognizes Electron's browser process as well as Node's main module; `require.main === module` alone did not start this Electron 45 runtime in the first real smoke. The renderer sees only `window.still.invoke(channel,payload)` and `player`, `library`, `settings`, `source`, `error` subscriptions. IPC is accepted only from this window's main frame at the packaged renderer URL. New windows, navigation and renderer permission requests are denied; Node integration is off, context isolation and sandboxing are on. Chromium audio output is muted. The app uses a dark native theme without changing the OS theme.

Local decoding runs in the app-owned foobar2000/Beefweb backend. Apple Music is an independent, capability-gated official-web adapter; absence of a verified host remains unavailable. The build does not require buying Cider, registering for Apple Developer, or entering a developer token. Optional research modules do not activate themselves as the default source. Account sign-in and protected/full-song playback remain a separate acceptance item.

## Portable state and backend

Source runs store data in `Still/data`; the directory package stores data beside `Still.exe` in `data`. `STILL_DATA_DIR` selects a different directory, including Chromium's profile/cache. The backend is always `backend/foobar2000` beside the source root or `Still.exe`. There is no ancestor discovery or fallback to `D:\foobar2000`. `STILL_FOOBAR_DIR` is a developer diagnostic override and disables automatic startup. A missing/invalid manifest, occupied port or startup failure keeps the custom UI open with actual unavailable diagnostics and an explicit retry action. No settings initialization writes volume, output or DSP.

The dedicated backend uses its own portable marker/profile and loopback-only port 18880. The window and IPC become usable before background startup completes, and an unverified process/port cannot receive bridge reads or commands. `initialize({start:true})` starts only the verified executable with hidden UI; `start:false` is read-only. Reused instances are never claimed or exited. Normal quit synchronously cancels intents, gives stop a bounded normal completion opportunity, then gracefully exits only the owned process without waiting behind a hung HTTP fence. Only branded evidence of that exact session/PID exit can end its pending transport lifetime. Failure preserves the window/diagnostic and allows another explicit quit; it never reports a false stop or kills the original application. See the bridge contract for details.

For one-time migration, `scripts/seed-library.js --data-dir <absolute path>` produces a read-only plan from the captured real existing-playlist snapshot. Adding `--execute` uses the real library service in a stage, reads metadata/covers from actual music, verifies each playlist occurrence/order, and exclusively commits a new `library.json`. An existing library is never overwritten. Source and packaged data are seeded separately; no blanket data-directory copy is performed. The reviewed snapshot has 12 playlists, 324 occurrences and 217 unique existing local files; the executed source seed produced 217 valid records and 92 covers. Reports live under `docs/evidence` and the target data directory.

The desktop performs a real backend `librarySnapshot()` then `library.importFoobar(snapshot)` when supported, at startup and after reconnect. This imports a STILL copy of the backend's exposed existing playlists. It does not claim the backend exposes its entire media library. Native STILL playlist edits affect the app copy. Playback and queue requests resolve library IDs in main and send `{path,subsong}` locations. CUE subsongs remain part of track identity.

Playback state is read back on commands and polled at 600ms without overlapping polls. Source availability changes are broadcast independently so a backend reconnect enables the real local controls. The bridge's redundant poll timer is disabled. Library synchronization runs independently, one scan at a time, with a 30-second failure backoff; bootstrap/player mapping use the last complete library. Paths map to IDs including subsong. `player:order {id}` uses the real numeric backend enum; unsupported Apple controls reject. No startup volume write is made.

`source:select` changes browsing only. `player.source` follows actual playing/paused adapter readback, and the coordinator cancels superseded generations, keeps materialization/verification outside its short transition lane, and waits for independent output-release evidence before switching engines. An owned-backend directory reload is a separate cancellable resource barrier only at explicit playback. Main and renderer use generation/revision gates to reject stale events. The [architecture contract](architecture-contract.md) specifies the adapter and IPC details.

The IPC extension `playlist:removeItem {id,index}` removes one occurrence, and `playlist:moveItem {id,fromIndex,toIndex}` moves one occurrence. `player:play` accepts an optional `startIndex` into its `trackIds` order and checks that the chosen occurrence matches `trackId`. Missing or unsupported selected tracks reject clearly. Missing or unsupported neighbors are skipped in the playback order while remaining visible in the library; the command result and player event include `skippedCount` for the UI.

Closing waits for in-flight library synchronization before disposing services. A reconnect invalidates synchronization from an older connection. Initial/minimum window dimensions are clamped to the primary display work area in device-independent pixels; Electron retains native Windows DPI handling. The renderer combines its reduced-motion preference with the OS media query. Renderer crashes and startup/load failures are visible; missing application files do not produce a placeholder success page.

Settings merge partial updates within `lyrics`/`appearance`, validate ranges/types and reject unknown keys. `showOriginal` and `showTranslation` cannot both be false. Persistence syncs a unique same-directory temporary file then atomically renames it; queued writes snapshot caller patches and merge against the latest successful state. Failed writes clean up temporary files and preserve the last committed state. Invalid existing JSON is retained with an `.invalid-<timestamp>` copy before fallback defaults are used.

## Cover art and lyric imports

Library cover URLs use `still-cover://art/<filename>`. The protocol resolves only recognized image extensions under the real `data/covers` directory, rejecting path traversal, other hosts and real paths escaping that directory. It does not expose a general file reader. Renderer CSP should allow only its own files, data images and this cover scheme.

Lyrics import uses a native picker with the service's `supportedFormats` extension array, falling back to `lrc`/`txt`. Main sends the chosen local path to `lyrics.importFile`; renderer payloads cannot select arbitrary local files. Music import likewise uses the native file/folder dialog. Library reveal uses the library's track ID, never an arbitrary renderer-supplied path.

After native music import commits, main records any new authorized music directories with `backend.preparePaths({paths,deferRestart:true})`. Pending directory changes are reported as `importReport.pending/restartRequired` and do not stop or restart current playback. Already configured paths may be checked with `foobar.prepareLocations` without playback. On a later explicit local play, the coordinator confirms cancellation/stop, applies roots only to an owned stopped backend, and starts the requested selection. Reused external instances cannot be reconfigured. Backend rejection leaves the saved library intact and reports a warning. Folder imports check tracks under the chosen folder only.
