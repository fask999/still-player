# 恢复副本与封面回收

库索引损坏或显式 reset 后，恢复副本用于保留原始数据。恢复副本中的封面 URL 可能是这些图片的唯一剩余引用；原媒体可能已移动，已有 metadata record 也不保证再次提取图片。因此不能把所有历史缓存都视为可重建文件。

只要 data 根目录直接子项中仍存在受管理的 `library-corrupt` / `library-reset` 名称家族，封面 GC 会跨重启保守跳过，并在准入前再次检查。保护不要求 `.json` 后缀，临时/user-kept 名、link 或目录也会触发；目录不可读或状态未知也不删除。该检查不解析损坏 JSON、不递归扫描归档目录，也不自动删除或迁移恢复副本。保留副本期间，孤立图片可能继续占用空间；正常退出不保证自动清空所有 orphan。

只有用户有意归档或移除这些恢复副本后，后续正常关闭才可恢复受限 GC。最稳妥的恢复方式是在应用关闭后保留/恢复完整 data，至少包括恢复 JSON 与所需 covers；应先核对归档完整性。仅移走 JSON 会解除这项保守保护，之后回收可能移除仅被该副本引用的缓存。仅恢复 JSON 也不会自动重提图片，普通 refresh 可因相同 size/mtime 复用旧 metadata。

GC 仍只允许在成功的 owned 正常退出与相关写入/获取 drain 完成后进行；正常关闭默认以 signal、250 ms 逻辑 deadline 和 64 个 maxDeletes 约束。已发出的物理 unlink 不会被谎报为已取消；pending 未真实结束时保留原 lifetime 和只读恢复状态，不重复发起同一轮删除。smoke、fatal、失败、未知或未闭态路径不执行该回收。

本轮源码验证使用 DI 与 synthetic 文件。另行审定的遗留 library seed stage 已在闭态核验和独立完整备份后实际清理，独立后验通过：精确移除 93 个文件和 2 个空目录，源库与 92 个已提交封面的字节和身份保留。备份继续保留；删除旧硬链接使源库 nlink 从 2 变为 1，并产生预期的 ctime 变化，不能据此声称净释放了同等磁盘空间。未清理已提交用户封面或库恢复副本；六个被 policy 拒绝清理的测试 fixture 不在此次范围内，仍保留原样。
