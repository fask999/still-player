# STILL implementation contract

The renderer is a custom Electron window. Local audio is decoded and played by STILL's own portable foobar2000 under `backend/foobar2000`; Beefweb on a dedicated loopback port is its control transport. The original installation, its backup and music files are preserved. The custom renderer never creates an HTMLAudio/AudioContext, and Chromium audio in that window is muted.

The native window minimum width is 480 device-independent pixels (clamped to a smaller work area), with the existing 680-DIP minimum height likewise clamped. Native Windows borders can make the renderer client area slightly narrower; portrait/narrow layout must therefore remain usable near 464 CSS pixels. Layout follows current client width/height, not the operating system's orientation or a changed display configuration. Pure size/DOM/CSS tests do not establish actual secondary-monitor/DPI behavior.

Apple Music is a separate subscription source. The selected product route is the official Apple Music website in a compatible native web host, using Apple's own sign-in and protected playback. The main process only enables capabilities actually supplied by a verified adapter; an absent adapter returns a real unavailable state. A DRM capability probe is not evidence of account authorization, subscription-library access or full-song playback. Cider and self-signed developer credentials are optional research code, never the default connection or a prerequisite for this build.

## Browsing and playback ownership

`source:select {source:'local'|'apple'}` changes only browsing. It returns `{selectedSource,sources}` and emits `source`; `source:status` returns the same shape. Bootstrap includes these fields. Each source describes its actual status, availability, message and explicit capabilities. Local status also includes `backendStatus` and `backendDiagnostic`. `backend:retry` is an explicit user action offered only in normal product mode, never in read-only smoke mode.

`player.source` is independent: `local` or `apple` only when a real adapter reports playing/paused, otherwise null. `lastSource` may retain the last observed source for stopped-track metadata. Source selection does not create a playback request, pause, resume, stop, change volume or change output. The bottom bar follows `player.source`.

`playback-coordinator.js` coordinates engine intents. A newer play/control synchronously invalidates old adapter commits via `cancelPending()`; its returned promise is a barrier for already dispatched transport writes, not full playlist construction or progress verification. Preparation occurs outside the resource transition lane. Same-engine B/pause/stop can enter while A is preparing or verifying. Only output handover and necessary owned-process lifecycle work occupy the transition lane. Each await is followed by a generation check before another destructive action. Cancelled promises reject with `STILL_CANCELLED`.

Before explicitly starting another engine, the coordinator cancels pending old commits, confirms a real stop, and requires `releaseOutput({signal})` to return `{released:true,evidence}`. A stopped/paused UI label alone is insufficient. Local release uses the exact selected CoreAudio endpoint and a temporary shared Initialize probe; the reverse direction requires temporary exclusive Initialize availability with no Start and immediate release. Missing mappings, uncertain transport settlement or failed probes block the target. These are moment-in-time access checks, not a DAC-rate measurement or proof about which application held a device. Playback ownership is assigned to the target only from actual readback; failed starts do not fabricate a source.

Player states include monotonic `generation`/`revision`. Epoch and read-sequence guards reject stale reads, main gates player events, and the renderer discards older versions. Old poll results cannot reverse a newer stop. Existing applications outside STILL can still change devices or playback; conflicting observed engines are reported explicitly.

## Renderer bridge

`window.still.invoke(channel, payload = {})` returns a promise. `window.still.on(channel, callback)` returns an unsubscribe function. Main emits `player`, `library`, `settings`, `source`, and `error` events. Errors reject with a useful plain message. The renderer handles unavailable backends explicitly.

Main channels:

- `app:bootstrap` → `{ library, player, settings, capabilities, version }`.
- `library:list` → `{ tracks, playlists, folders }`; `library:import` `{kind:'files'|'folder'}` opens native picker and indexes accepted music; `library:refresh`; `library:remove` `{ids}`; `library:reveal` `{id}`.
- `playlist:create` `{name}`; `playlist:rename` `{id,name}`; `playlist:delete` `{id}`; `playlist:setTracks` `{id,trackIds}`; `playlist:addTracks` `{id,trackIds}`; `playlist:removeTracks` `{id,trackIds}`. All return the library snapshot.
- `player:state`; `player:play` `{trackId,trackIds?,playlistId?}`; `player:toggle`; `player:pause`; `player:stop`; `player:next`; `player:previous`; `player:seek` `{position}` seconds; `player:volume` `{volume}` normalized 0..1. Main resolves track IDs to paths via library before calling bridge.
- Local `player:play` also accepts `source:'local'`. Apple playback uses `source:'apple'` with adapter-supported item IDs/types and is rejected before handover unless a real playback capability exists. Main never accepts arbitrary Apple playback URLs or local file paths from this payload. Toggle/seek/volume route to the actual engine; unsupported methods reject. `apple:status` returns the sanitized source descriptor. `apple:authorize`/`apple:pair`, `apple:library`, and `apple:search` are capability-gated; they never manufacture an authorization or library result. The unavailable official-web adapter offers none of these actions.
- `queue:list`; `queue:add` `{trackIds}`; `queue:remove` `{index}`; `queue:clear`. Returns `{items:[{index,trackId?,title,artist,path?}],...}`. Queue is separate from saved playlists.
- `player:order` `{id}` uses the numeric enum ID read from the real backend; the player state includes `playbackOrder:{id,name}` and `playbackOrders:[{id,name}]`. Do not hardcode foobar enum indexes.
- `audio:outputs` → `{outputs,selected,...}`; `audio:select` `{id}` uses exact exposed backend output identifier; `audio:details` returns capabilities, selection readback, source details, measured state and explicit unknowns.
- `settings:get`; `settings:update` `{patch}` → settings snapshot.
- `lyrics:resolve` `{trackId,force?}` → LyricsDocument; `lyrics:search` `{trackId,query?}` → `{results,source,status,error?}`; `lyrics:preview` `{trackId,candidate}` → LyricsDocument; `lyrics:bind` `{trackId,candidate}` → LyricsDocument; `lyrics:import` `{trackId}` native picker; `lyrics:offset` `{trackId,offsetMs}`; `lyrics:unbind` `{trackId}`.
- `app:window` `{action:'minimize'|'maximize'|'close'}` optional; `app:openDataFolder`; `app:restoreInfo`.
- `app:exportDiagnostics` `{layout?}` is an explicit user action in the existing audio/settings dialog, available only when normal-mode `capabilities.exportDiagnostics` is true. It accepts no path or extra fields, stores a new allowlisted JSON snapshot under this app's `data/diagnostics`, and returns `{saved,filePath,recordedAt}`. Optional layout contains only `{width,height,devicePixelRatio,horizontalOverflow,appReducedMotion,systemReducedMotion,effectiveReducedMotion,accentColor}`: positive integer CSS viewport dimensions up to 32768, finite DPR 0.25–16, booleans, and six-digit hex colour. Effective motion is the OR of app/system preferences. These values are measured by the user's own renderer save action, not UI automation; no DOM text, screenshot or account data is accepted. It reads only the current services and bounded existing observation history; it does not open a host, authorize, play or configure an output. Provider objects, credentials, tokens, cookies, headers, URLs and arbitrary error text are excluded. Read-only smoke cannot export.

## Canonical data

Track: `{id,path,subsong,title,artist,album,albumArtist,duration,trackNumber,discNumber,year,genre,codec,sampleRate,bitsPerSample,channels,coverUrl,valid,supported?,playbackUnsupportedReason?}`. Missing values remain null/empty and are not invented. `coverUrl` is a safe local URL or data URL. IDs are persistent and tied to a canonical path plus foobar subsong (default 0). Playlist: `{id,name,trackIds,createdAt,updatedAt,source?,sourcePlaylistId?}`. Existing foobar lists are read and imported as app copies with `source:'foobar2000'`; original lists are preserved. Explicit user imports and real existing foobar entries are the only sources of library content; no fabricated library entries. Unsupported container/subsong playback is rejected with a clear explanation rather than playing a different subtrack.

Player: `{available,state:'playing'|'paused'|'stopped'|'unavailable',source:'local'|'apple'|null,lastSource,generation,revision,position,duration,volume,currentTrackId?,currentTrack?,output?,queue?,error?}`. Only local currentTrack maps to known library paths/subsongs; an Apple ID can never resolve to a same-named local record. Source metadata and output configuration are distinct. Position seconds. Real adapters are polled and read back.

Settings defaults include `{lyrics:{fontSize:30,lineHeight:1.75,translationSize:18,showOriginal:true,showTranslation:true,onlineEnabled:true,cacheEnabled:true,preferredSource:'lrclib'},appearance:{reducedMotion:false,localView:'albums',accentColor:'#A8B9FF'}}`. `localView` accepts only library/albums/artists/playlists. Older preferences retain their values and receive the missing defaults. `accentColor` accepts only a string matching `^#[0-9A-Fa-f]{6}$` and is normalized to uppercase; CSS expressions, whitespace, short/alpha hex and nonstrings reject without changing the last committed settings. The renderer previews the accent and saves explicit changes through the existing partial `settings:update` patch, preserving lyrics/motion/navigation fields. Readable text/focus and semantic error/warning colours remain independently derived rather than blindly using an arbitrary chosen colour. `capabilities.persistUIState` is true in normal mode, false in read-only smoke; only explicit local navigation may save the remembered view when this capability exists. Settings merging preserves unspecified values. At least original or translation display must stay enabled. The file picker uses `lyrics.supportedFormats` so unsupported formats are not advertised.

LyricsDocument: `{trackId,status:'ready'|'plain'|'instrumental'|'not-found'|'network-error'|'parse-error'|'searching',kind:'word'|'line'|'plain'|'instrumental'|'none',source,title?,artist?,lines:[{startMs,endMs?,text,translation?,words?:[{startMs,endMs,text}]}],plainText?,offsetMs,fromCache,local,bound,error?}`. Word mode requires real timestamped words. Translation is aligned by timestamp, never array index. Positive offset delays lyric highlighting relative to audio; renderer uses `audioMs - offsetMs`. Manual binding/local imports take precedence. Requests must be isolated by track identity.

## Service module ownership

- `src/main/foobar.js`: playback executor. Exports `createFoobarService({foobarDir,dataDir,...})` with async `initialize`, `getState`, `play({paths?,locations?:[{path,subsong}],startIndex})`, `toggle`, `pause`, `stop`, `next`, `previous`, `seek(position)`, `setVolume(volume)`, `queueList`, `queueAdd(pathsOrLocations)`, `queueRemove(index)`, `queueClear`, `outputs`, `selectOutput(id)`, `audioDetails`, `librarySnapshot`, `close`. `librarySnapshot` returns `{playlists:[{id,name,items:[{path,subsong,title,artist,album,duration,...}]}]}`. It may expose extra diagnostics; document them. No renderer dependencies. The queue keeps its playlist item references alive. A 202/204 response alone is not playback proof: wait for indexing and read back real player progress/error state.
- `src/main/library.js`: media executor. Exports `createLibraryService({dataDir,onUpdate,dialog,shell})` with async `initialize`, `list`, `importFiles(paths)`, `importFolder(path)`, `importFoobar(snapshot)`, `refresh`, `remove(ids)`, `getTrack(id)`, `getTracks(ids)`, `createPlaylist(name)`, `renamePlaylist(id,name)`, `deletePlaylist(id)`, `setPlaylistTracks(id,ids)`, `addPlaylistTracks(id,ids)`, `removePlaylistTracks(id,ids)`, `reveal(id)`, `close`.
- `src/main/lyrics.js`: lyrics executor. Exports `createLyricsService({dataDir,getTrack,getSettings})` with async `initialize`, `resolve({trackId,force})`, `search({trackId,query})`, `preview({trackId,candidate})`, `bind({trackId,candidate})`, `importFile({trackId,path})`, `setOffset({trackId,offsetMs})`, `unbind({trackId})`, `close`. Export parser/alignment helpers for tests.
- `src/main/main.js`, `preload.js`, settings module, packaging scripts and package.json: desktop executor. Integrates service methods and contracts, uses safe IPC, handles app lifecycle and library mapping. Node integration disabled in renderer, context isolation enabled. Local file protocol or safe data URLs for cover art. Service module filenames must be preserved.
- `src/main/backend.js`: exclusive owner of the app's private foobar process/profile lifecycle and pending authorized music directories. `initialize({start:false})` verifies without launching. Normal product startup may launch only the manifest-verified dedicated executable with hidden native UI. It never discovers an ancestor installation. Imported directories stay pending until explicit playback safely stops and reloads an owned process; import itself does not stop the current song. App quit stops its controlled local playback and gracefully exits only its own process.
- `src/main/playback-coordinator.js`: desktop executor; generic cancellation/output ownership described above. Engine adapters do not import renderer code. Optional Apple modules remain owned by the Apple integration executor.
- `src/renderer/*`: sole Terra writer after playback transport proven. Plain JS/CSS/HTML is sufficient; Electron packaging is independent.

Services are CommonJS for compatibility unless the desktop executor confirms an alternative across all owners. Tests use `node --test` and do not require an active GUI unless explicitly integration tests. Package dependencies may be requested through the desktop executor, who alone edits package.json. All user data is under the app data directory selected by main, separate from shipped source. Do not write tags to audio.
