# CUE 播放校验和只读租约

显式播放先用库里的精确 path 和 subsong 重新核验 CUE、引用文件、曲目数与授权目录，再准备内核路径。关联变化时提示刷新或重新导入。连接到已核验的专属内核会话后，应用取得固定原生助手的只读租约，并在持锁期间用同批曲目再次调用库的校验。原生提交前还检查操作代次、租约品牌和当前输出。

已经存在于后端播放列表的普通曲目可以继续从当前列表选择。桥接器先双读实际列表内容，核对原选择 token、当前会话和输出，再为本次操作签发仅在主进程内有效的 WeakMap 凭证。凭证只匹配这次确认的原始 path 字符串和 subsong。库只接收同步验证函数。选中操作结束时撤销凭证，取消和会话或输出变化也使验证失效。未知显式 CUE、CUE 关联路径上的未知 subsong、播放列表和归档仍由库拒绝。恢复、前后切歌和跳转会双读相应的当前列表和队列候选，防止用旧候选派发操作。

如果真实后端把 CUE 曲目报为引用音频及 subsong，补齐播放列表时提交已核验的 CUE 源。应用在租约内按缺少的精确曲目再次确认归属。与 CUE 共用物理文件的普通曲目仍按自己的身份处理。加载、复制及播放读回使用实际后端返回的精确路径和 subsong。CUE 路径比较保留大小写。

应用在持锁后发起的原生请求，包括相关列表元数据读取，都会在调用前登记。已登记的租约绑定这一个内核会话和同一 CUE 请求。停止、超时和逻辑取消后，原生读取仍可能继续，租约保留到该会话的真实 child 和 Job tree 退出凭证到达。尚未交给 Native 的操作在取消后可关闭自己的租约。某个租约失效时只取消正在使用它的操作。已持有的同一会话和同一请求可复用一个助手。

最多同时保留八个助手，核验操作也有数量和时限。上限或未核验的清理会给出明确提示。需要清理本次会话保留的租约时，正常退出 STILL 后重新打开。正常退出先撤销待处理操作，再等待真实内核退出和助手关闭。尚未证明退出的会话保持其租约。

首次启动和重载前的库校验适用于本次请求。旧 profile 的自主预载及发现候选前读取的已加载列表元数据处于这个持锁窗口之前。应用发起的 CUE 补齐、复制、当前列表选择和控制提交处于窗口内。测试使用合成文件、Native 助手协议替身和生产后端管理器的合成 child/tree 事件，覆盖租约复用、数量上限、取消与超时、严格文件身份、同一会话退出回收和下一会话恢复。真实内核的 CUE 读取和音频验收另行记录。
